# 股票监控日报

默认中文，以美股已完成的最新常规交易日为准。用户指定日期、名单、收件人或阈值时优先遵从。`stock.txt` 默认取当前工作目录，支持 `# 持仓股票`、`# 候选池股票` 两个分组，股票代码每行一个。不要把示例代码视为永久名单。

## 执行

1. 运行 `scripts/scan.py --list /绝对路径/stock.txt --state /绝对路径/analysis/stock-monitor-state.json --output /绝对路径/analysis/stock-scan-YYYY-MM-DD.json`。首次运行初始化支撑位；以后读取并更新状态。脚本只计算和筛选，不负责新闻解释或邮件发送。先核对数据日期、缺失项、公司行动和基准匹配；行情未完成或不可用时不冒充当日数据。
2. 对扫描结果中的 `research` 项目做新闻搜索，同时查看当日大盘的重要新闻及**持仓股和候选池股票**的新消息。优先公司公告、SEC 披露、财报或宏观数据发布方，再看可靠媒体；市场综述可参考可靠财经媒体。先比较大盘、板块 ETF 或可比公司篮子与股票方向及幅度；共同波动可共用一次搜索。个股相对基准显著偏离、支撑破位、或绝对跌幅较大时再搜个股新闻。名单中的股票即使未触发价格阈值，若有财报、指引、监管、重大交易、产品或业务公告，也可进入个股要闻。对照事件发布时间与交易时段。结论标记“已确认事件”“可能相关”“原因未确认”，不能把同日新闻直接说成唯一原因或编造贡献比例。若本地已有 `market-move-attribution` skill，可借用其中的归因方法；本日报只需简短结论。
3. 程序给出的支撑区是候选。首次初始化或破位重算时，AI 检查 `support_candidates`：均线是否上行或走平、成交密集区是否相合、历史反应是否稳定、是否有财报跳空等削弱参考价值的因素。选择最近的有效区间，给“高／中／低”置信度和一句理由；等级表示证据一致程度，不是守住概率。用 `scripts/record_support.py --scan ... --state ... --ticker AAPL --candidate-index 1 --confidence 中 --reason '...'` 保存复核结果；如果候选都不成立，保留未初始化状态并在日报说明。只有日线 OHLCV 时必须称“成交密集区估计”，不能声称是真实持仓筹码或成本分布。日常只更新“接近／盘中跌破／收盘跌破／收回”；连续两个收盘低于区间下沿才将旧区间失效并重算。候选为空时区分“数据不足”和“数据足够但附近无有效候选”，不捏造支撑位。对尚无确认支撑的股票，额外执行下方阶段新低检查。
4. 将扫描结果和已核实新闻写成 Markdown 日报，同时转成简洁 HTML 邮件正文。结构：标题与行情截至时间；**今日大盘新闻**（主要指数与板块表现、油价／利率等关键背景、2–4 条最相关的新闻及其对市场的可能影响，通常 2–4 段）；重点提醒（达到异动、支撑触及／破位、阶段新低等条件的持仓及候选股）；**个股要闻**（同时覆盖持仓股和候选池股票，只列有实质新增信息者；每条尽量交代事件内容、关键数字、发布时间、对业务或预期的意义、当日股价与同业或大盘对照、归因确定性和直接来源）；支撑位变化；来源与数据缺口。**不要附“全部股票”或未触发股票简表**；仍须扫描完整名单，原始扫描 JSON 保留全部数据。新闻细节以可核实信息为限；没有可信新消息的股票无需逐只占位，可在段末简述未发现值得单列的消息。`stage_low.notify=true` 时，在标题或开头明确写“阶段新低提醒”，列明 120/252 日口径、前低与本次收盘价；邮件发送随当日日报进行，除非用户另行要求单独提醒。每条重点写股票涨跌、大盘与板块 ETF 或可比公司篮子的相对表现、归因等级和链接。新闻事实与价格归因分开表述，避免在重点提醒与个股要闻重复大段文字。保留 Markdown 归档；PDF 仅在用户要求时制作。
5. 正式运行完成日报后，默认使用**已连接的 Gmail 插件**发送给当前 Gmail 账号本人；用户明确要求“仅预览”、测试、演练或 `--dry-run` 时不发送。先用 Gmail 的 `get_profile` 核对已连接账号，再用 `send_email` 发送；`to` 设为 `me`，邮件标题包含报告交易日，正文 MIME 类型为 `text/html`，内容取本次生成的 HTML 日报。发送前核对交易日、报告内容、收件账号与是否已发送过同一交易日版本；去除“仅本地预览／未发送邮件”等占位文字，避免邮件中的本地相对文件链接失效。发送后检查返回的邮件 ID 和 `SENT` 状态并记录结果，不因响应不明确而盲目重发。Gmail 插件不可用或当前账号无法确认时，保留日报并说明缺少的条件；不要静默改用其他邮箱或 SMTP。

## 扫描规则与口径

- 持仓绝对涨跌达到 3%，候选池达到 5%，或相对板块 ETF／可比公司篮子偏离达到 2 个百分点，进入研究。没有有效板块或可比公司基准时，以相对大盘偏离 2 个百分点作为临时筛选依据，并在日报注明归因限制。绝对跌幅达到 5% 无论基准如何都进入研究。支撑位触及／破位独立触发。
- 先判断价格是否主要跟随大盘、板块 ETF／可比公司篮子，还是显著偏离；这只是搜索路由与证据，不是因果证明。在添加股票时优先选贴近其业务的板块 ETF，写成 `sector=XLK`。没有合适 ETF 时，可选 2–4 只业务、客户和市场较相近且流动性足够的可比公司，写成 `peers=DECK,NKE`。首次选择要核对代码和可比理由，后续沿用；业务变化或公司行动时复核，不每天重新搜索。ETF 和可比公司篮子不能混为同一种板块指标。日涨跌采用各可比公司等权平均，并在日报列出成分与各自涨跌；成分分化或某只公司有独立事件时，不能笼统说“跟随板块”。任一可比公司缺少同一交易日及前一交易日的数据时，不计算篮子，用相对大盘作临时筛选并标明缺口。
- 默认使用 AKShare `stock_us_daily(adjust="qfq")` 的前复权 OHLC。选 `--provider tiingo` 时，密钥优先取显式 `--tiingo-key-file /绝对路径/credentials.json`，否则取 `TIINGO_API_KEY` 环境变量，最后才读取当前工作目录的 `tiingo.json` 中的 `api_key`。云端作业通过 Secrets 将原始密钥注入 `TIINGO_API_KEY`，不要提交密钥文件。Tiingo End-of-Day 使用 `adjOpen/adjHigh/adjLow/adjClose/adjVolume`，再归一到最新交易日现价口径。令 token 只出现在请求头，不写入扫描 JSON、日志、日报或 skill 文件；缺少或无效时明确报错，不静默换源。Tiingo 是收盘日线，不用于盘中实时提醒。可用 `--provider yahoo` 选 Yahoo；其历史 OHLC 用当日 `Adj Close / Close` 缩放到同一复权口径。日线价位分布只能估算。所有支撑区、均线、当前价必须在同一价格口径。行情可能延迟；日报写明来源、抓取时刻和最新交易日。切换来源时程序将旧支撑位标为待复核并重新计算候选，不直接沿用。不同来源不在同一次扫描中混用。
- 支撑位初选：20、50、200 日均线与近 120 日按典型价聚合的成交密集区；区间宽度由 14 日 ATR 估计。密集区是日线近似，不能视为逐笔成交价位。程序置信分仅供排序，AI 必须独立复核。
- **无可信支撑时的阶段新低提醒：**以当天收盘价分别比较此前 120、252 个交易日（不含当天）的最低收盘价；120 日约半年，252 日约一年。跌破幅度须超过 `max(前低的 0.5%, 14 日 ATR 的 0.25 倍)` 才触发，优先标记为 252 日新低；数据不足 120 个此前交易日时标资料不足，不冒充阶段新低。盘中新低但收盘收回只在日报备注，不发此提醒。首次触发即列入日报重点；同一天不重复提醒，以后只有从 120 日升级为 252 日、或较上次提醒价再跌超过 `max(1%, 14 日 ATR 的 0.5 倍)` 时重复提醒。上次提醒已超出最近 120 个交易日，则视为新一轮。阶段新低是风险信号，不等同未来必跌或买卖建议；搜索同期公司及市场事件时仍遵守归因证据规则。
- 扫描结果、状态、Markdown 日报用独立文件保存。异常或数据缺失要明确写入日报，不用旧数据填补当天。

## 测试与依赖

云端预扫描由 `.github/workflows/tiingo-daily-scan.yml` 在北京时间周二至周六 08:30 触发，也可手动运行。它使用 GitHub Actions Secret `TIINGO_API_KEY`，调用 `scripts/cloud_scan.py`，仅在所有股票与基准均为当日已完成的美股交易日且数据完整时，保存 `data/latest-scan.json`、`data/scans/YYYY-MM-DD.json` 与 `data/stock-monitor-state.json`。这一步只取数和预筛选，不生成日报或发送邮件；网页端计划任务须读取最新扫描结果，完成新闻、AI 支撑位复核及 Gmail 发送。若首次运行因缺少 Secret 失败，先在仓库的 Actions Secrets 配置原始 Tiingo 密钥，不要上传 `tiingo.json`。

安装 `scripts/requirements.txt`。当前 `stock.txt` 有九只持仓，AAPL 在观察池；LULU 配有 DECK、NKE 可比公司。测试运行：

`python stock-daily-monitor/scripts/scan.py --list stock.txt --state analysis/stock-monitor-state.json --output analysis/stock-scan-test.json --dry-run`

Tiingo 示例：本地可复制项目根目录的 `tiingo.example.json` 为 `tiingo.json`，将 `api_key` 改为真实密钥（该文件已被 `.gitignore` 忽略）；云端则把原始密钥配置为 `TIINGO_API_KEY` Secret。然后给上述命令添加 `--provider tiingo`。显式 `--tiingo-key-file` 仍可指定其他本地 JSON，并覆盖环境变量。其 REST 日线字段与认证方式见 [Tiingo 官方文档](https://www.tiingo.com/documentation/end-of-day)和[连接说明](https://www.tiingo.com/documentation/general/connecting)。

`--dry-run` 不写状态，也不发邮件；如要测试状态更新，用另一个临时 state 路径。脚本输出仅是预筛选，仍需按上述步骤完成归因、AI 支撑复核与日报。
